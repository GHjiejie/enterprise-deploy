# 可视化企业配置与打包

构建控制台用于开发者在本地配置企业版本。企业模块开关在打包时固定，客户应用运行后继续使用构建常量；用户角色权限与后端授权保持独立。

## 启动与使用

在项目根目录执行：

```bash
npm ci
npm run configure
```

浏览器打开 `http://127.0.0.1:5180/`。启动控制台无需设置 `APP_PROFILE`。

1. 选择已有企业，或选择「新建企业」并填写企业标识。
2. 勾选开放的模块，至少启用一个模块；依赖模块也需要启用。
3. 从已启用模块中选择默认页面。
4. 选择生产环境或预发布环境。
5. 点击「保存配置」只保存；点击「保存并构建」保存当前选择并立即构建。
6. 等待真实构建日志和结果，成功后点击「预览构建结果」或「下载交付包」。

关闭当前默认模块后，需要重新选择默认页面。表单无效时不会保存或启动构建。保存失败会保留输入；检测到其他页面或编辑器修改同一配置时，会提示冲突，可明确选择重新加载后再编辑。

修改尚未保存时切换企业会提示是否放弃修改。构建期间配置表单锁定，完成后可以继续编辑。选择的环境只用于本次构建，不写入企业 JSON。

如果 5180 端口已被占用，可以指定另一个端口：

```bash
CONSOLE_PORT=5190 npm run configure
```

使用终端显示的 HTTP 地址访问，保持终端运行；按 Ctrl+C 停止控制台。

## 配置与产物

可视化保存直接写入 `config/profiles/<企业标识>.json`，继续使用现有严格 schema 和模块装配校验。这些文件是可评审、可纳入版本控制的最终配置，不需要在业务页面增加企业名称判断。

「保存并构建」会保存当前企业配置，并将全部有效企业配置复制成隔离快照。构建子进程显式使用 `APP_PROFILE`、内部快照目录 `APP_PROFILES_DIR` 和本次任务的 `APP_BUILD_ID`，执行现有 `npm run build -- --mode ...`。构建期间外部编辑器再修改原配置，也不会改变本次固定的模块组合。

成功后的常规产物仍在 `dist/<企业>/<环境>/`。控制台另外在 `dist/.console/<任务 ID>/` 保存固定快照与 `.tar.gz` 交付包，包内包含静态应用与 `release-record.json`。结果只有在子进程成功退出、发布记录与任务 ID/企业/环境/配置一致、所有文件摘要通过并打包完成后才会显示成功。

预览从该次任务的固定快照启动独立的本地 HTTP 服务；随后更改配置或再次打包，不会把已有预览替换成另一份模块组合。预览地址随控制台进程生效。控制台重启后当前任务状态和预览会清空；磁盘上的配置、常规产物与已生成交付包保留。

日志在页面实时显示，只保留最近 100,000 个字符。构建失败不会提供旧产物作为本次结果；此前其他成功任务的交付包保持原样。

## 本地写入与并发

控制台只监听 `127.0.0.1`，所有配置与构建请求通过同源接口。浏览器只能提交结构化配置和允许的环境，不能提交文件路径或任意 shell 命令。配置保存使用版本摘要和原子替换，并拒绝符号链接配置目录或文件。

同一项目的控制台使用 `.console-build.lock` 串行处理配置写入和构建，避免多个端口或页面覆盖同一份输出。正常停止会终止正在运行的构建子进程并释放锁。若进程异常终止留下锁，应先确认没有构建进程运行，再手动清理该锁；工具不会自动删除来源不明的锁。

控制台是本地开发工具，不会加入企业静态包，也不提供远程管理、多人登录或运行时企业配置接口。企业交付仍需要完成测试、代码评审和真实目标部署校验。

## 测试与持续集成

```bash
npm run check
npx playwright install chromium
npm run test:console
```

控制台浏览器测试使用独立临时配置目录，验证新增、编辑、保存、冲突、实际构建、下载与固定预览，不修改仓库中的企业配置。`APP_PROFILES_DIR` 是内部构建快照及测试隔离用途，普通使用不需要设置。

CI 会动态发现所有已保存并提交的企业配置，无需手写企业名单。新增企业参加发布验收时，仍需提供该企业和环境对应的可信后端兼容声明；控制台不会从模块开关推导或伪造后端授权。当前 `config/backend-policies/demo-*.json` 为演示声明。
