# 可视化企业配置与打包

构建控制台用于开发者在本地配置企业版本。模块开关在打包前固定，客户应用只获得所选模块的业务实现和活动注册表；用户角色权限与真实后端授权保持独立。

## 启动与使用

```bash
npm ci
npm run configure
```

打开 http://127.0.0.1:5180 ，启动控制台无需设置 `APP_PROFILE`。

1. 选择已有企业，或选择「新建企业」并填写企业标识。
2. 勾选开放模块，至少启用一个；必要依赖也需要启用。
3. 从已启用模块中选择默认页面，并选择生产或预发布环境。
4. 「保存配置」只保存；「保存并构建」保存当前选择并立即构建。
5. 等待配置校验、编译与裁剪、快照复验、打包复验等实际阶段和日志。
6. 成功后查看裁剪状态、开启/排除模块，预览固定版本，下载交付包或裁剪报告。

关闭当前默认模块后需要重新选择入口。无效表单不会保存或构建。保存失败、构建失败均保留输入；其他页面或编辑器修改同一配置时提示冲突，可明确选择重新加载后再编辑。未保存时切换企业会提示是否放弃修改。

构建期间表单锁定，完成后可以继续编辑；环境只用于本次构建，不写入企业 JSON。端口占用时可以运行 `CONSOLE_PORT=5190 npm run configure`，使用终端显示的 HTTP 地址。保持终端运行，Ctrl+C 停止控制台。

## 配置、裁剪与固定产物

可视化保存写入 `config/profiles/<企业标识>.json`，沿用严格 schema、版本摘要和模块装配校验。配置可评审并纳入版本控制，不需要在业务页面添加企业名称判断。

构建将全部有效企业配置复制成隔离快照，子进程显式使用 `APP_PROFILE`、内部 `APP_PROFILES_DIR` 和任务 `APP_BUILD_ID`，执行统一 `npm run build -- --mode ...`。外部编辑器之后修改原配置不会改变本次模块组合。

Node/控制台拥有完整模块目录，客户 bundler 只获得本次启用模块的虚拟导入。构建检查私有依赖、输出来源和实际文件；共享上传等公共能力可以保留，禁用模块的私有业务、样式及专属资源不能通过改名或混合 chunk 随包进入。

常规产物在 `dist/<企业>/<环境>/`。控制台在 `dist/.console/<任务 ID>/` 保存固定 `site/` 和 `.tar.gz`，包内包含静态应用、`pruning-report.json` 与 V2 `release-record.json`。只有以下步骤全部成功才展示本次预览和下载：

1. 子进程成功退出，身份、企业、环境、配置、任务 ID 一致。
2. V2 记录、裁剪报告、完整清单和实际文件全部复验。
3. 固定快照复制完成，按同一规则再次验证。
4. 生成受限 ustar/gzip 包，完整检查全部成员后在隔离临时目录解包，再验证包内 V2、报告和每份文件。

归档禁止绝对/父目录路径、重复成员、符号链接、硬链接、扩展头和特殊文件，并限制压缩/展开大小、单文件大小及成员数。未知或额外文件、缺失报告、V1、摘要不符或错配置均失败。前端绿色裁剪状态来自验证结果，不能仅凭模块有关闭项或日志里出现“通过”显示成功。

预览使用该任务的固定快照启动独立 HTTP 服务；后续配置或打包不会替换已有预览。下载和已启动预览的后续访问都会重新检查固定制品，外部篡改会拒绝。预览随控制台进程生效；重启清空内存中的任务和预览，磁盘配置、常规产物及交付包保留。

日志只保留最近 100,000 个字符。失败任务没有本次成功结果，不能把此前任务的包当作本次下载；已有成功任务仍保持自己的固定身份。

## 本地写入与并发

控制台只监听 `127.0.0.1`，通过同源结构化接口操作，浏览器不能提交任意文件路径或 shell 命令。保存使用版本摘要和原子替换，拒绝符号链接配置目录/文件。

同一项目的多个控制台使用 `.console-build.lock` 串行处理保存和构建。完整构建协调器另外使用 `dist/.locks/<企业>-<环境>.lock`，保护 CLI 与控制台可能共用的输出。正常停止终止构建子进程并释放所持锁；异常残留时先确认 PID/构建 ID 没有仍在执行，再人工清理。工具不自动删来源不明的锁或历史证据。

控制台是本地配置工具，不提供远程管理、多人登录或运行时企业热切换。它可以构建合法组合用于本地评估，但目标是否允许部署，由独立可信交付策略决定；保存更多模块不会自动放宽目标策略。

## 测试、发布与安全边界

```bash
npm run check
npm run test:pruning
npx playwright install chromium
npm run test:console
```

浏览器测试使用独立临时配置，验证新增、编辑、保存、冲突、真实构建、裁剪状态、固定预览、报告与安全下载，不修改仓库企业配置。`APP_PROFILES_DIR` 用于内部快照和测试隔离，普通使用不用设置。

CI 自动发现已提交企业。新增企业要参加目标交付验收，另需对应的后端兼容声明和模块交付策略；具体命令见 [交付说明](delivery.md)。`config/backend-policies/demo-*.json` 与 `config/delivery-policies/demo-*.json` 为演示声明。

当前业务页面没有真实 API，演示权限选择器即使在 production 模式也不能作为生产认证。物理裁剪与前端页面权限都不代替服务端逐请求校验身份、企业权益和资源归属。本轮 P1–P5 正在实施并验证，P6 真实后端待接入；最终验收范围以整改验证记录为准。
