# 企业模块物理裁剪整改验证记录

验证日期：2026-10-15（Asia/Shanghai）

范围：本仓库 V2 方案的 P1–P5、本地可视化控制台、CI 配置和本地文件系统交付适配器。

结论：本地验收通过；`qianshi` 的 staging / production 新产物仅交付视频模块的私有实现。P6 真实身份、业务后端授权和生产平台接入尚未完成。

本记录对应[物理裁剪技术方案](enterprise-build-pruning-design.md)，作为[整改前风险报告](local-risk-assessment-2026-10-15.md)的后续验证，不改写原始风险证据。全部结论限于受控源码、构建工具和本地测试环境，不代表已发布到真实生产环境。

## 1. 实现与证据身份

- 浏览器活动目录由 `virtual:enterprise-modules` 生成，只导入启用模块。完整目录仅供构建与配置工具使用。
- 图片/视频业务分离，模型广场数据、各模块样式和专属资源按目录归属；公共上传与预览独立保留。
- 构建检查真实依赖、私有导入方向、CSS / URL 内联资源、输出来源及最终字节。构建协调器等待 Vite 完整结束，再生成裁剪报告、V2 记录并复验。
- 控制台对常规输出、固定快照和安全解包后的交付包复验；下载和预览后续访问再次核对固定身份及字节。
- 发布与回滚要求当前可信交付策略，V1 或超过当前模块上限的历史版本不能发布。新的公开资源集合与站点由同一 `current` 指针切换。

验证使用 Node.js `v25.6.0`、Vite `8.3.4` 和锁文件中的依赖。八份最终实际产物均具有相同的公开源码输入摘要：

## 4. 负向边界与独立审阅

已验证拒绝以下情况，且失败不提供本次成功制品或保留可冒用的成功记录：

- 禁用私有实现被引用，共享层反向导入私有实现，已启用模块互相穿透私有实现；符号链接目标按真实路径判断。
- CSS `url()` 的大小写、带空格文件名、`image-set()` 字符串、跨私有资源及共享层私有资源引用。
- `new URL(..., import.meta.url)` 的禁用/跨模块资源内联；动态 URL 和无法静态枚举的计算型 `import()`。
- 未登记的 NUL 虚拟模块、未经批准的外部 HTML 脚本、未知插件输出。
- 最后清理 hook 改写文件、追加旧文件；输出混入源码、map、报告篡改或额外空目录。
- 同企业/环境并发写入；不同企业并发则保持隔离。
- 前置兼容配置损坏后重建失败，旧成功记录失效。
- tar 路径穿越、重复成员、链接、特殊类型、扩展头、截断、追加数据、校验错误、数量/大小超限。
- V1 发布、检查规则不被目标允许、当前模块上限收缩后的不合规 V2 回滚、资源名称碰撞与复制后篡改。

独立审阅发现的 CSS/URL 内联、未知虚拟 ID、动态导入、前置失败和归档限额问题均补充了真实失败用例并修复。当前没有为未支持形态默认放行：worker、SharedWorker 与 WASM 在接入专门归属适配前明确拒绝。

## 5. 历史资源与生产接入限制

原有七份 V1 常规产物已核验并备份在忽略版本控制的 `dist/.legacy-artifacts/<buildId>`；另保留原控制台 V1 快照的受控备份。整改前 `qianshi/production` 常规目录已被本轮新构建替换，其原始身份、摘要和文件证据保留在原风险报告中；不声称仍持有该份完整旧生产字节副本。

本地交付测试已验证：模块上限收缩时，新 `public-generations` 的公开资源不包含不合规旧版本，私有归档和旧根资源不会被自动删除，回滚不合规包被拒绝，切换发生在完整准备与校验后。

**真实站点首次迁移必须同步采用 [Nginx 新配置](../deploy/nginx.conf)**，站点根为 `current/site`，资源根为 `current/assets` 对应的新公开集合；继续使用旧根 `/assets/` 配置仍会暴露旧资源。本机没有 Nginx 可执行程序，未启动真实 Nginx 或执行服务器/CDN 切换；本次验证的是本地适配器和公开目录集合，不能替代真实环境上线验收。

本地控制台已重启到本轮实现，可在 `http://127.0.0.1:5180/` 使用。当前产物仍是明确标记的业务演示，production 模式没有真实身份或 API 接入。前端裁剪、演示权限和 demo 策略不能证明服务端授权有效；已被客户下载或缓存的旧字节也无法召回。
